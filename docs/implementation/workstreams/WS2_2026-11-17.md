# WS2 — Intelligence and automation: implementation record, 17 November 2026

Branch: `ws2-intelligence`. Scope this round: depth in BRAIN, TEAM and MISSION, plus honest local retrieval in AI. AUTO and ANALYTICS were not changed.

Everything below runs in the browser against local Dexie records scoped to the current organisation. Nothing calls a model or an external provider. Where a provider would be needed, the screen says so.

## ARL-BRAIN-001 Knowledge home: Overview tab (`/o/:org/brain/home`)

**Status:** Implemented and verified.

**What changed.** The Overview tab is now a knowledge workspace. It has three columns: collections, a searchable record list and the selected record.

- **Collections** (`knowledgeCollections`) are created from the column and carry a description, an owner and a default review interval. Each shows a live count, and choosing one filters the list.
- **Knowledge records** (`knowledge`) can be created and edited. Each holds a title, collection, summary, content, tags and an optional review interval. It also holds **provenance** (written by a person / model-generated / imported), **cited sources** (a Company Brain source with a page or section, or a named external reference) and **related-record links** (other knowledge records, assertions, decisions and sources). Backlinks show in both directions.
- **Search and filter.** Search covers title, content, tags, collection and source names. Every search term must match, with light plural folding, and title matches rank first. Filters: status (active / draft / needs review / verified / archived), provenance, freshness (fresh / due soon / overdue / stale / never reviewed / needs attention) and reviewer. Sort options: best match, recently updated, review date and title. The list shows a result count and a clear-filters control.
- **Freshness** is computed only from recorded dates. A verified record goes stale once its review interval has passed, or due soon in the last 14 days. A record in review becomes overdue after its due date. A draft is "never reviewed", not "fresh".
- **Review workflow.** A record moves through these steps:
  1. Request review, naming a reviewer and a due date.
  2. Verify, or request changes (a note is required).
  3. Archive, or restore to draft.

  Every step appends to the record's history, which shows who, when, the reviewer, the due date and the note.
- **Verification rules.** Verify needs the `edit_knowledge` capability, the record in review and some content. Model-generated or imported text cannot be verified until it cites a source. If a verified record's substance changes (title, summary, content, provenance or sources), saving returns it to review. Changing tags or the collection does not.
- **Deep link:** `?record=<id>` selects a record. Records reached from the Recent tab and from Ask Arlovi citations open here.
- **Stats row:** verified, in review (with how many are overdue), stale, and model-generated but unverified. Each stat applies its filter when clicked.

The earlier registry overview (assertion stats, quality meters, recent sources, top entities) moved to the top of the **Quality** tab. The **Recent** tab now includes knowledge records. The "Search knowledge" primary action focuses the workspace search. The older inspector drawer is still reachable as "Inspect assertions and sources".

**Code.** New module `src/applications/brain/knowledge/` holds `model.ts` (pure rules), `Workspace.tsx` (UI) and `knowledge.css`. `internalPeople` moved to `brain/people.ts` and is re-exported from `index.tsx`.

**Seed.** `src/domain/seeds/brain.ts` adds 3 collections and 7 records covering every state: verified/fresh, in review due soon, model-generated and overdue with no source, verified/stale, draft, verified with two sources, and archived.

**Persistence.** Verified by an e2e test across reloads: the collection, the record, its status and its review history all survive.

**Responsive.** At 1440 px the layout uses three columns. Below 1200 px collections become a horizontal chip row. Below 900 px the list and the record take turns, with an "All records" back button. No horizontal overflow at 390 px, checked by test and screenshot.

**Tests.**

- `e2e/ws2-knowledge-workspace.spec.ts`: 4 tests (search and filter guard; create → review → verify → reload → edit returns to review; Ask Arlovi citation; phone layout).

**Gaps.**

- `RECORD_ROUTES` in `src/platform/attention.ts` has no entry for `knowledge`, so global search cannot open these records. See the proposal below.
- Rich text is plain text with preserved line breaks.

## ARL-TEAM-003 AI employee (`/o/:org/team/agents/:id`)

**Status:** Implemented and verified.

**What changed.**
- **Overview** has a new "Can it run work?" card. It lists what is configured (contract revision, granted scopes, permitted actions, approval level) next to why the AI employee cannot run work: contract status, activation blockers, no model provider connected, and no trusted execution server. It shows "Cannot execute" and links to model routing.
- **Permissions** became an inline **contract editor**:
  - **Approval level:** suggest / draft for review / act with approval, chosen with radio cards.
  - **Permitted actions:** an editable list (add, edit, remove).
  - **Tool scopes:** grant or withdraw a scope, set its access (read / draft / act), remove it, or add a new scope with an identifier, label, access and an optional provider requirement.
- **Validation:**
  - A scope that needs an unconnected provider cannot be granted; its checkbox is disabled and the save is refused.
  - An act scope needs the "Act with approval" level and always requires approval for each use.
  - Empty or duplicate permitted actions are refused, as are duplicate scope identifiers.
- **Saving:**
  - Before you save, the screen lists every pending change (unsaved-changes notice).
  - Each save is one revisioned patch, with an audit line that lists the changes.
  - Queued work is marked for re-authorisation unless the only change is a label.
- **Work** keeps the current assignments and adds **Assignment history**. It merges AI work assignments, blocked execution requests, mission tasks and project tasks, newest first. Each row says what happened and that nothing was executed by a model.

**Code:** `src/applications/team/contract.ts` (pure), `ContractPanels.tsx`, `team-contract.css`.

**Persistence:** Verified by e2e reload: approval level, the new permitted action and the new granted scope all persist.

**Responsive:** No overflow at 390 px. The save bar stays sticky.

**Tests.**
- `tests/unit/ws2-team-contract.test.ts`: 6 tests.
- `e2e/ws2-team-contract.spec.ts`: 2 tests.

**Gaps.**
- Team-level "agent teams" as a separate resource were not added. Departments and the organisation chart already cover grouping.
- The legacy "permission inspector" drawer (overflow action) still edits grants only.

## ARL-MISSION-003 Mission overview (`/o/:org/mission/missions/:id`) and ARL-MISSION-004 Plan → Timeline

**Status:** Implemented and verified.

**What changed.**
- **Mission brief card.** Holds the objective, in scope, out of scope, constraints and how success is judged, with a completeness meter. It is edited inline with validation: the objective and success measure are required. Saving also updates the mission summary shown in the library.
- **Execution status card.** It is read only from step and task records:
  - steps that ran locally;
  - steps stopped at a provider boundary;
  - approvals outstanding;
  - open AI tasks, stated as never generated.

  The label is one of: plan awaiting approval, paused, partly blocked, waiting on approval, in progress (local steps), completed or cancelled.
- **Milestones.** A milestone has a name, a due date and linked tasks. Its state is computed: reached only when every linked task is verified; overdue after its date; at risk within 3 days; otherwise on track. A milestone with no tasks is "empty". Milestones can be added, edited and removed. Each shows progress and its linked tasks.
- **Team tab → participant roster.** Explicit participants (people or active AI employees) are combined with task assignees, each listed once.
  - You can add a participant with a role (owner / contributor / reviewer / approver / observer), change roles, and remove a participant who holds no tasks.
  - AI participants show "Can execute: No · Model not connected".
  - Choosing an AI employee as approver shows a warning that approval gates still need a person.
- **Plan → Timeline** now opens with a date axis that plots milestones, today and the mission due date, with an accessible list of the same milestones. The existing dependency sequence stays below it.

**Code:** `src/applications/mission/brief.ts` (pure), `BriefPanels.tsx`, `mission-brief.css`.

**Seed:** mission `nl-missions-060` gets a full brief, 3 milestones and 2 participants.

**Persistence:** Verified by e2e reload: brief, milestone and participant all persist.

**Responsive:** No overflow at 390 px on the overview or the timeline. Timeline labels flip side near the right edge.

**Tests.**
- `tests/unit/ws2-mission-brief.test.ts`: 7 tests.
- `e2e/ws2-mission-brief.spec.ts`: 2 tests.

**Gaps.**
- Tasks have no start or end dates, so the timeline does not draw task bars. It does not predict finish dates, by design.
- AI employees appear in the add-participant list only after the TEAM seed has loaded in that browser. See the proposal below.

## ARL-AI-001 Chief of Staff chat (`/o/:org/ai/chat`) and the shared engine

**Status:** Implemented and verified.

**What changed.**
- `t2_shared/engine.ts` adds a "Written knowledge" topic. It ranks knowledge records deterministically by the words in the question, ignoring stopwords and never returning archived records. The answer quotes each record's own summary, says whether it is verified, in review, draft or model-generated, and cites the records. Its limits state that nothing was paraphrased or generated.
