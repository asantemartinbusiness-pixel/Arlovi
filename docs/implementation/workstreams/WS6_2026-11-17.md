## Screens

### ARL-FORMS-002 Visual Form Builder — `/o/:org/forms/forms/:id`
- **Changes:** the field inspector has a new "Show this question only when…" editor. It reads only earlier questions. When the source question has options, the answer is picked from those options. It writes `show` rules into the form model, and each rule can be removed.
- **Working actions:** Add condition, Remove condition.
- **Persistence:** the rules are saved in `body.logic` on the form record. The live form enforces them after a reload (e2e).
- **Status:** Verified.

### ARL-FORMS-004 Form Submissions — `/o/:org/forms/forms/:id/submissions`
- **Changes:** a view switch with three options:
  - **Inbox:** the existing view.
  - **Results table:** one row per response and one column per question. Sensitive answers are redacted unless revealed, and each reveal is logged.
  - **Question summary:** option counts with meters for choice questions; average, median and range for numbers; yes/no counts for checkboxes; recent and distinct answers for text.
- **CSV export:** the primary Export CSV action and the in-table download now share one RFC 4180 exporter. It also guards against spreadsheet formula injection.
- **Responsive:** the table scrolls inside its own region at 390px, and the page itself does not scroll sideways.
- **Status:** Verified.

### ARL-FORMS-006 Form Analytics — Responses tab
- **Changes:** a per-question answer distribution is now on this tab. Chart labels changed to Q1…Qn so they no longer overlap, and the table names each question with the same number.
- **Status:** Implemented. Covered by a screenshot only.

### ARL-IT-003 Incident Detail — `/o/:org/it/incidents/:id`
- **Lifecycle stepper:** Open → Triage → Mitigate → Resolved → Postmortem.
- **Severity and owner:** edited inline, and each change writes a timeline entry.
- **Gate on each step** (`stageBlockers`):
  - Triage needs a severity and an owner.
  - Mitigate needs a mitigation note.
  - Resolve needs what fixed it, plus diagnostics that ran after the incident opened, either in this session or recorded in the audit log.
  - Postmortem needs at least 40 characters.
- **Status sync:** each stage writes the matching status (`investigating`, `mitigating`, `resolved`, `closed`), so the queue tabs stay correct. Older actions that change the status directly still move the stage.
- **Timeline tab:** a composer for notes, mitigation steps and verification entries. Entries are stored in `body.timeline`.
- **Status:** Verified, including after a reload.

### ARL-IT-002 Incident Queue
- **Changes:** new sortable Stage column.
- **Status:** Verified.

### ARL-IT-001 Operations — Changes tab
- **Changes:** a change-request register (`it_changes`) with a list and an editor:
  - Plan, change window, scope, reversibility, testing and target (local, or remote and not connected).
  - Risk is scored from points, and each reason is listed.
  - A rollback plan is required above low risk. Submission is gated.
  - The approval records a named approver who must not be the requester.
- **States:** draft → submitted → approved/rejected → implemented → rolled back. An approved change on a remote target can only be recorded as implemented outside Arlovi.
- **History:** the record's audit events are shown with it.
- **Seeds:** two Northline change requests.
- **Status:** Verified.

### ARL-IT-004 System health — Provider status tab
- **Changes:** an asset and configuration register (`it_assets`).
  - A "Local evidence" card shows values the browser measured now (origin, IndexedDB, processors, storage, online).
  - Registered assets are labelled Local or Remote · not connected.
  - Configuration is edited as `key = value` lines, and a diff is shown and recorded in the audit event.
  - Remote assets take a "hand check" that records who looked, when, and what they saw.
- **Seeds:** three assets.
- **Status:** Verified.

### ARL-IT-008 Security — Access tab
- **Changes:** access reviews (`it_access_reviews`).
  - Starting a review lists every member of the organisation with their role and warning signs: no second factor, more than 30 days inactive, automated agent, suspended or invited.
  - Revoke or modify needs a reason, and so does keeping a flagged member.
  - The review can be completed only when every member is decided.
  - Account changes are left to Admin › Members (linked), because no identity provider is connected.
- **Status:** Verified.

### ARL-CONNECT-005 Connection Detail — Sync tab and Overview
- **State card:** one explicit state with a legend of all five:
  - **Pending setup:** there is no valid saved mapping.
  - **Configured:** a valid mapping is saved.
  - **Simulated:** the saved mapping has been run on the documented sample row.
  - **Connected:** only when the capability is `verified_external`.
  - **Disconnected:** the record is disabled, suspended or revoked.
- **Mapping editor:** maps each source field to an Arlovi field, with a transform (case, trim, decimal to minor units, normalised date). It is saved per connection in `body.mapping`.
- **Validation:**
  - Required: an external-id match key and a title.
  - Duplicate targets are flagged.
  - Warnings for type mismatches and for unmapped fields that would be dropped.
- **Simulation preview:** labelled as sample data, not provider data.
- **Overview tab:** shows the setup state with a link to the mapping editor.
- **Status:** Verified.

### ARL-WEB-008 Quality report — SEO tab

- The Forms builder Preview tab still validates without saving responses. Responses are saved from the live form on Design & publish › Embed.

- Seed records for changes and assets appear only in workspaces seeded after this change, or after a seed-version bump, which is a shared file.
